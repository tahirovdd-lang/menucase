# MenuCase

[Открыть сайт](https://tahirovdd-lang.github.io/menucase/)

Статическая витрина ресторанов на GitHub Pages. Список ресторанов, меню и фотографии публикуются из ветки `main`.

## Добавить ресторан

1. В `menus.json` добавьте запись с названием и уникальным адресом, например `{"name":"Art Cafe","slug":"art-cafe"}`.
2. Создайте `menus/art-cafe.json` с полями `restaurant` и `items`. Для пустого меню используйте `{"restaurant":{"name":"Art Cafe"},"items":[]}`.
3. Для каждой позиции в `items` укажите уникальный `id`, название `name`, категорию `category` (`food`, `drinks` или `alcohol`) и цену `price`. Дополнительно можно указать `description`, `photo`, `section` для подкатегории блюд, `markers` для ингредиентов и `nutrition` для КБЖУ. В `restaurant.logo` можно указать путь к логотипу. Пути к изображениям задавайте от корня репозитория, например `menus/art-cafe/pizza.webp`.
4. После публикации откройте меню по адресу `https://tahirovdd-lang.github.io/menucase/?restaurant=art-cafe`. Когда в меню появятся позиции, на странице будет доступен QR-код для скачивания.

Для ингредиентов используются записи вида `{"name":"Томат","x":45,"y":60}`, где координаты заданы в процентах размера фото. Для КБЖУ используйте числовые поля `calories`, `protein`, `fat` и `carbs` в расчёте на 100 г.

Правки публикуются коммитом в GitHub. В статической версии нет кабинета с входом через Google или Telegram, регистрации и уведомлений. Код прежнего сервера и бота сохранён в репозитории отдельно от витрины. Храните в `menus.json` и `menus/` только данные, которые можно показать гостям.

## Полная версия с кабинетом

Серверная версия использует те же исходники и запускается как Cloudflare Worker. Статический адрес GitHub Pages остаётся доступен отдельно до переключения.

1. Создайте в Cloudflare R2 хранилище `menucase-data`. Привязка `BUCKET` и команда сборки уже указаны в `wrangler.jsonc`.
2. В Cloudflare **Workers & Pages** создайте Worker из репозитория `tahirovdd-lang/menucase`, ветка `main`, корень репозитория. Имя Worker — `menucase`. Достаточно стандартной команды развёртывания `npx wrangler deploy`: Wrangler запустит `node build.mjs`.
3. В **Settings → Variables and Secrets** Worker добавьте следующие значения.

| Переменная | Значение |
|---|---|
| `OWNER_GMAIL` | Gmail системного администратора |
| `OWNER_TELEGRAM_ID` | Telegram ID системного администратора |
| `TELEGRAM_ADMIN_CHAT_ID` | Telegram ID получателя уведомлений |
| `MENUCASE_TELEGRAM_BOT_USERNAME` | Имя бота без `@` |
| `REGISTRATION_BOT_PUBLIC_KEY` | Значение `MENUCASE_PUBLIC_KEY` из логов существующего бота |
| `GOOGLE_CLIENT_ID` | Идентификатор веб-клиента Google OAuth |
| `GOOGLE_CLIENT_SECRET` | Секрет веб-клиента Google OAuth. Сохраните с типом **Secret** |

4. Добавьте в Google Cloud точный URL `https://<домен-Worker>/auth/google/callback` к разрешённым URI используемого клиента.
5. На BotHost добавьте переменную `MENUCASE_SITE_URL` со значением `https://<домен-Worker>` и запустите обновлённую версию бота. Сохраните прежние `BOT_TOKEN` и каталог данных бота с его ключом. Запускайте только один экземпляр бота на этом токене.
6. Откройте `/admin` на новом адресе. Проверьте оба способа входа, регистрацию, получение уведомления и публикацию меню. Новое хранилище изначально пустое. Для восстановления действующих записей из прежнего хостинга нужен отдельный перенос в приватное хранилище R2.

Для существующего QR-кода важен адрес, сохранённый внутри него. После перехода на другой домен скачайте QR-коды на новом адресе.
